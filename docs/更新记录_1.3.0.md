# Windows 语音输入法 1.3.0：纠错学习

日期：2026-09-12  
适用：Windows 11 x64，1.3.0 预发布构建。  
本文件是技术设计 v3.0 的增补；涉及纠错学习和数据库升级的规定以本文件为准。

## 使用方法

1. 完成一次语音输入，在程序的“最近输入”打开“对照与编辑”。也可以先从“历史记忆”载入需要修改的记录。
2. 切换到“原始片段修订”，选择片段，修改错误写法，点击“保存编辑”。例如，把“请安排人材盘点。”改为“请安排人才盘点。”。
3. 点击“查看纠错候选”，或打开“词库 → 纠错学习”。程序会列出“人材盘点 → 人才盘点”等局部纠错建议。
4. 选中候选，点击“确认学习…”。检查标准写法和来源，可修改词条边界、分类、权重，以及是否加入全局词库，然后确认。
5. 保持设置中的“识别时使用已启用词库”开启。下一次录音选取热词时，已学习词条会获得优先级；后续润色会保护命中的标准写法。

本版从**本程序内保存的手动修订**发现纠错。不会读取在 Word、微信、浏览器等外部应用中的后续改字。片段修订也不会自动改写已经输入到外部文档中的文字。

### 可管理的内容

| 操作 | 结果 |
| --- | --- |
| 搜索、状态筛选 | 查看当前项目的待确认、已学习或已忽略记录 |
| 查看来源 | 查看修改前后上下文、会话、片段及编辑版本，最多展示最近 30 个来源 |
| 确认学习 | 新建或合并已启用词条；确认前可调整建议 |
| 忽略 | 保存忽略偏好，后续相同纠错不会重新进入待确认列表 |
| 恢复候选 | 有有效来源的已忽略项重新进入待确认列表 |
| 撤销学习 | 删除本次新建词条，或恢复合并前的词条设置；该组写法转为已忽略 |

撤销学习会检查词条版本。词条在学习后又发生变化时，程序保留最新状态，并提示到词库手动调整，避免覆盖后续修改。删除已学习词条，也会将关联的纠错记录设为已忽略。

## 开关与学习范围

新增设置：“从手动修订中发现纠错候选（本地比较，确认后学习）”，默认开启，点击“保存设置”后生效。

发现候选需要同时满足：

- 开启“保存本地文本记忆”。
- 开启“允许词条整理（新会话默认）”。
- 开启纠错候选发现功能。
- 当前会话允许用于词条整理。
- 来源为已确认、已发布的识别片段，且修订成功保存。

关闭纠错开关会暂停后续发现及候选确认，保留已有记录和已学习词条。关闭一条会话的学习许可会移除它的有效纠错来源；重新开启许可不会自动重放过去的修改。未成功保存的修订不计为学习来源，保存重试成功后再同步。

升级不会扫描旧编辑日志并批量学习。已有“记住此写法”、AI 领域词库生成及历史提词功能仍可独立使用。

## 候选发现与重复统计

候选发现使用本地 Unicode 文本差异比较，不调用 DeepSeek，不增加词库 AI Token 用量。模型自动润色结果不会触发纠错学习。

程序优先寻找专名、术语、英文拼写和大小写等局部变更。它会跳过纯标点变更、识别到的语气词删除、数字变化、部分否定词变化，以及超过差异预算的大幅改写。规则无法理解所有语义，中文词条边界也可能包含邻接词；因此候选始终需要用户确认，可在确认窗口修正。

| 规则 | 限制或行为 |
| --- | --- |
| 文本比较 | NFC 规范化，按 Unicode 标量比较；修改前后各不超过 20,000 个标量，UTF-16 长度各不超过 40,000 |
| 差异预算 | Myers 差异距离最多 128；超过预算不生成建议，原有编辑保存流程不受候选生成影响 |
| 自动候选长度 | 新旧写法各 2—32 个 Unicode 标量；中文扩展范围不超过 16 个标量 |
| 自动发现数量 | 每次最多 8 组；每个片段当前编辑状态最多保留 32 组有效纠错 |
| 候选记录容量 | 每个项目最多 5,000 组；达到上限不再新增组，原有组仍可更新来源，正文仍可保存 |
| 标准词条确认 | 可调整为 1—64 个字符；权重 1—5，旧写法仅用于追溯 |
| 重复计数 | 同一项目、同一组新旧写法，按不同有效来源片段统计；同一片段重复保存或重试不会重复计数 |
| 多次纠正 | 至少 3 个有效片段时标记“多次纠正”；确认窗口建议权重由 4 改为 5，仍需手动确认 |
| 来源预览 | 每组最多展示最近 30 个上下文；次数统计包含全部有效来源 |

纯中文插入或删除通常不作为自动纠错候选；单字词、长词及未发现的词条可通过“记住此写法”或词条管理手动添加。输入法的长语音及一次长按全文润色流程继续沿用 1.2.0 的实现，纠错发现只在用户保存片段修订时执行。

## 如何影响下一次识别

确认后，词条进入当前项目或全局词库，状态为已启用，同时置顶并开启润色保护。词条会参与既有热词选择流程，每轮仍最多选择 200 个热词；实际是否被选中还受项目范围、其他词条优先级和词库总开关影响。

同范围已有同名词条时进行合并，保留其分类和有效来源，取较高权重并开启置顶、保护。同名禁用词条会提示先到词库手动启用。历史提取词条经明确确认后成为独立的纠错学习词条，删除旧来源不会删除它。

这不是对云端模型进行训练，也不保证以后每次都识别正确。识别热词用于提高标准写法的优先级；润色保护避免模型随意改写命中的词条。程序不按旧写法进行全文无条件替换，不会为了“学习”扩大原有轻量润色权限。

本地生成候选不上传上下文。确认后的标准词条按照已有设置，可随识别热词或润色请求发送给相应服务商；与普通词库使用方式一致。

## 数据与一致性设计

### 数据结构

| 结构 | 作用 |
| --- | --- |
| `AppSettings.LearnCorrections` | 独立控制候选发现；旧设置缺少该字段时采用默认值 |
| `EditState.Corrections` | 保存当前编辑状态对应的纠错标记；旧 JSON 缺少字段时视为空 |
| `corrections` | 加密保存新旧写法、状态、关联词条及撤销学习所需的旧词条设置 |
| `correction_sources` | 加密保存修改前后上下文和来源版本；主键为候选 ID 与片段 ID |
| `correction_decisions` | 标记明确确认或忽略的偏好，避免没有来源后被当作临时候选清除 |

文本负载沿用 Windows 当前用户的 DPAPI 保护。项目、会话、片段 ID、版本和索引字段用于查询，不声称整个 SQLite 文件均已加密。撤销学习的旧词条快照不复制历史正文证据。

### 状态变化

| 当前状态 | 事件 | 结果 |
| --- | --- | --- |
| 无记录 | 符合条件的修订成功保存 | 建立待确认记录及来源 |
| 待确认 | 相同纠错出现在其他片段 | 合并来源、更新次数 |
| 待确认 | 用户确认 | 原子写入词条及已学习状态 |
| 待确认 | 用户忽略 | 保存已忽略偏好 |
| 已忽略 | 用户恢复且来源有效 | 回到待确认 |
| 已学习 | 用户撤销且词条版本未变化 | 删除新增词条或恢复旧设置，转为已忽略 |
| 待确认 | 所有来源失效 | 删除无来源候选 |
| 已学习或已忽略 | 所有来源失效 | 清理来源上下文，保留明确词条或忽略偏好 |

### 写入与撤销

- 修订正文和纠错来源在同一个 SQLite 写事务内提交。正文写入或加密失败时，候选也回滚。
- 确认时重新核验来源会话许可、项目、片段发布状态及原文和编辑版本。陈旧界面不能批准已经失效的来源。
- 候选状态与词条变更以同一事务提交，重复确认不会新建重名词条。
- 连续编辑、撤销、恢复原文和删除片段会同步当前有效来源；撤销操作本身不被当作一次反向纠错来学习。
- 删除会话、关闭会话学习许可或自动清理历史时移除对应来源；未确认且没有其他来源的候选随之删除。
- 已确认词条与忽略偏好独立管理。删除全部相关历史后，仍可能保留新旧写法这组词和偏好，但不保留候选的来源上下文。需要移除已学习词条时，到词库删除。
- 删除项目会清除该项目的纠错记录及项目词条；明确添加的全局词条继续保留。

## 升级与回退

1. 从托盘完全退出旧版。
2. 备份 `%LOCALAPPDATA%\RealtimeTranscription\` 整个目录，再运行 `VoiceInput-Windows-x64-1.3.0.exe`。
3. 新版继续读取原 Key、设置、历史和词库，将数据库 `user_version` 从 1 升级为 2，并新增纠错表；不清空旧数据。数据库升级测试使用构造的旧版数据执行，不能代替对用户实际数据库的备份。

**旧版 1.2.1 不能直接打开已升级的版本 2 数据库。** 如需回退，先退出新版，将升级前的完整备份恢复到原位置，再运行旧 EXE；回退备份不包含升级之后新增的数据。不要通过手动调低 `user_version` 强行回退。

## 验证结果与待验收项

117 项自动测试通过，0 项失败，包含原有 95 项及新增 22 项纠错回归。Windows x64 自包含单文件发布成功。新增覆盖本地规则、Unicode、候选持久化、去重计数、热词和润色保护、四项许可、忽略恢复、连续撤销、过时确认、事务失败回滚、保存重试、已有词条合并、来源删除、跨项目隔离及旧数据库升级。

测试使用真实 SQLite 临时库、测试专用保护器和模拟网络；没有调用真实付费 API。当前环境是 Linux，尚未运行 Windows GUI、DPAPI、真实麦克风及外部应用输入测试，不能据此认定实机兼容性已经通过。

Windows 实机验收建议按以下顺序执行：

1. 备份后升级，检查旧 Key、历史和词库可读取。
2. 在程序内将“人材盘点”改为“人才盘点”，保存后检查待确认、确认窗口和词条。
3. 在三个不同来源片段完成相同修改，检查次数和“多次纠正”标记；重复保存同一片段，次数不增加。
4. 检查忽略、恢复、撤销学习、关闭会话许可及删除来源后的结果。
5. 重启检查状态保留，并用实际账户验证学习词条对下一轮识别的效果。

详细自动测试日志和 EXE 元数据见源码包 `verification/`，完整构建方式见 `README.md`。
