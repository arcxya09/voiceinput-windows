# 运行日志

从 VoiceInput 2.1.10 起自动启用。出现问题后打开“设置 → 麦克风与操作 → 导出运行日志”，保存一个 `.log` 文件，并在反馈中说明发生问题的大致时间、操作步骤及目标软件。

导出不要求录音空闲。即使麦克风准备或本地测试卡住，仍可通过设置页导出；后续测试、重启不会覆盖前一次故障的日志。文件内容为 UTF-8 JSON Lines，每行一个事件，便于直接阅读或按时间、进程和本轮标识筛选。

## 记录内容

| 范围 | 内容 |
| --- | --- |
| 运行环境 | 程序版本、Windows 版本号、进程与系统架构、运行时与音频库版本、启动方式 |
| 麦克风 | 枚举是否完成、端点数量和状态、默认设备角色、设备标识的哈希、选定和回退设备的各次尝试 |
| 原生采集 | 激活接口、读取音频格式、Initialize、设置事件、取得采集服务、读取设备周期、Start、首包与停止 |
| 时序 | 时间戳、调用线程、Apartment、本轮关联标识、首包和识别就绪耗时 |
| 识别与输出 | 连接和任务阶段、片段/字符计数、文字处理、转为手动复制、取消、复制粘贴结果和接受的输入事件数 |
| 故障 | 异常类型、HRESULT、有限内层异常与方法栈、清理失败、保存失败和退出阶段 |

不记录 API Key、凭据、录音、识别正文、提示词、词库内容、服务端原始响应、窗口标题、设备原始名称与端点 ID。异常的 Message、Data、ToString 和源码路径均不写入日志。日志仅保存在本机，不自动上传。

## 保存与大小

默认目录为 `%LOCALAPPDATA%\RealtimeTranscription\logs`。安装版和便携版均写入当前用户数据目录，无需管理员权限，也不依赖程序安装目录可写。

单个文件约 2 MiB，达到大小上限或跨 UTC 日期后新建文件；按 7 天和最多 10 个文件自动清理。正在写入或导出的文件不强行删除，解除占用后在后续清理中处理。记录使用有界队列在后台写入，不在录音线程执行磁盘写操作。

导出会等待本进程已接受的日志写入，并汇总近期文件的完整行。导出头部记录来源文件数、丢弃条数，以及日志写入故障造成的不完整状态；当前日志无法继续写入但旧文件可读时，仍可导出已有记录。导出失败或取消会清理临时文件，不用半截内容替换目标文件。

设置页会显示日志是否可用以及写入问题。磁盘不可写、空间不足、进程被强制结束或系统故障时，日志可能不完整；程序不会为等待日志而阻塞录音。程序尚未进入托管入口前的原生加载失败无法由这个日志系统捕获。

## Win10 麦克风排障

本次代码审查未找到可以确认“Win10 无法使用 WASAPI”的依据。设备枚举器释放、默认通信角色、MTA 线程间使用及现有共享事件参数都不能单独解释用户的失败。新增日志用于取得真实失败点及错误码。

设备构造中的系统调用可能阻塞；任务取消不能中断已经进入的驱动调用。因此会在每个关键调用之前记录开始，失败时记录异常，成功后进入下一阶段。最后一个开始事件有助于确定卡住的位置，导出过程独立于录音的互斥锁。

若其他录音软件可以使用同一麦克风，请在 VoiceInput 再现失败后导出日志。若整个程序无法打开，可先保留上述目录中的最新 `.log` 文件。
