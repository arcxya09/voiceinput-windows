# VoiceInput 2.5.0

## 直接输入到光标处

- 默认不再经过剪贴板：标准 Edit/RichEdit 文本框（记事本、WinForms、Delphi 等）通过 EM_REPLACESEL 一次替换选区，保留目标软件的撤销；其他软件通过一次 SendInput 发送整段 Unicode 字符，系统不会把它与实际键鼠输入交错。
- 2.1.4 曾逐字分批键入，部分软件出现个别文字被标点替换。本版整段一次提交；目标使用中文、日文或韩文输入法且处于开启状态时，先临时关闭目标输入法，等目标处理完这批字符后恢复原状态。无法确认输入法状态时不键入，改用粘贴。
- 多行正文、超过 4000 字、管理员权限软件拒绝输入或直接输入不可用且没有发出任何字符时，自动改用整段复制和一次 Ctrl+V。可能已部分输入时不粘贴重发，只复制完整正文并提示核对。
- “设置 → 麦克风与操作”新增“直接输入到光标处，不占用剪贴板”，默认开启；关闭后与 2.4.x 相同，始终整段粘贴。

## 输入焦点不再轻易丢失

- 文字跟随原窗口内的当前焦点。编辑器重建或切换内部控件、辅助功能元素变化、选区移动，不再导致降级为复制；投递前对当前控件重新检查密码、只读和禁用状态。
- 鼠标点击和滚轮不再停止自动输入，文字输入到松手时的光标处。其他按键仍停止自动输入。
- 其他窗口短暂占据前台（通知、提示、输入法模式提示）时给予 1.5 秒恢复时间；持续切到其他窗口才停止本轮自动输入。投递时最多等待 0.8 秒让原窗口回到前台，绝不向其他窗口输入。
- 按下说话键时窗口仍在激活、尚未产生焦点的情况，最多等待 1 秒取得焦点，不再直接转为仅复制。

## 验证

回归检查覆盖直接输入成功不写剪贴板、可能部分输入时只复制不重发、关闭直接输入后走粘贴、鼠标和滚轮不降级、子焦点变化继续输入及持续切换窗口后降级。Windows 冒烟检查在独立进程的普通文本框、富文本框和只处理 WM_CHAR 的自绘控件中读回中文、emoji 与组合字符，确认剪贴板未改动且未发送粘贴；并验证同窗口焦点切换后粘贴跟随新控件。

CI 环境没有中文输入法，临时关闭和恢复输入法的流程需要在实际的微软拼音、搜狗等输入法下复测。遇到问题可导出运行日志，`DirectInputCompleted` 记录了所用通道和未直接输入的原因，不含正文。
