## 使用变化

### 会话学习许可

“设置 → 允许词条整理（新会话默认）”是整理总开关，也决定之后新建会话的初始许可。

已有记录需要单独设置：在“历史记忆”载入记录，进入“最近输入”，勾选或取消“允许当前会话用于词条整理”。该操作立即尝试保存，无需再点“保存设置”。被单独禁止的会话不会因为总开关重新开启而参与提取。

关闭“保存本地文本记忆”时，可以修改已经保存记录的整理许可；程序只更新许可，不把此时的本地正文修订写入历史。没有保存的文本不能进入历史提取。

旧版未落库的许可无法从数据库推断。曾在旧版排除过的历史，请升级后检查并重新关闭其会话许可。

### 保存和重新载入

“未保存”计数包含片段和会话信息，并保留切换会话之前失败的写入。使用“设置 → 重试保存未保存内容”补写；显示保存完成之前，程序会等待存储确认。

重新载入一条仍有待保存内容的历史时，程序先尝试保存；持续失败则保留当前文字并提示，不用旧记录覆盖它。删除会话或项目后，其失败写入不会继续重试，也不会恢复已删除的数据。

关闭文本保存时，普通重试不会悄悄开启正文保存；仅许可保存失败时允许重试许可。持续无法写入磁盘时，请在退出前复制或导出文字。待保存内容保留在当前进程内，不能在磁盘写入失败的情况下承诺关机后恢复。旧版已经丢失的全文结果也不会被本次升级自动补回。

### 词库与预算

同一范围内按 NFC 规范化、去除首尾空白和不区分大小写的规则查重。手动修改权重、分类、启用状态等字段时，保留已提交的最新来源证据。候选确认后才参与识别。

启动时合并旧版已产生的同范围重复词条：优先保留手工或手动纠正项，再比较更新时间；合并有效证据，保留手工属性。重复组中有禁用项时保持禁用，避免升级意外启用词条。该合并在事务内完成，并可重复执行。

三个词库 AI 入口共用每日预算，以 **UTC 00:00** 为新一天，在中国标准时间对应 **08:00**。已知用量按实际返回值结算，未知请求保留预留额度；预算不包含 ASR 和普通全文润色。当前会话提取保留每次最多 5 批的规则，全部历史提取可继续其剩余批次。单批最多重试一次可重试的服务错误，候选和提取进度只提交一次。

## 技术增补

本节与 1.2.0 功能增补共同补充技术设计 v3.0；出现冲突时，以较新的增补为准。

| 层次 | 实现 |
| --- | --- |
| 会话模型 | 新增 `LearningRevision`，阻止旧全文或投递写入覆盖新的学习许可；旧 JSON 缺省为 0 |
| 编辑模型 | 新增 `UndoHistory`、`UndoPosition`；`Edits` 继续记录审计历史。旧记录首次操作时建立独立撤销状态 |
| 保存协调 | 以会话 ID 和保存类型跟踪最新待保存快照；失败片段保留所属引擎，重试覆盖已切离会话 |
| 一致读取 | `LoadSessionAsync` 在同一 SQLite 事务中读取会话及片段，供历史载入、导出和提取使用 |
| 词库写入 | `SaveUserTermAsync` 和 `ImportUserTermsAsync` 在串行写事务中读取最新记录、查重和校验容量 |
| 历史提取 | 当前会话与全部历史共用提交实现；候选与游标原子写入，短时持有词库锁，等待网络时不持锁 |
| 来源清理 | `SaveSegmentAsync` 只在片段版本写入被接受后清理失效证据，并与修订共同提交或回滚 |
| 用量 | `ReserveTermBudgetAsync` 在同一事务中按 UTC `day` 累计和预留，避免并发请求分别通过余额检查 |

保留既有 SQLite 表结构、DPAPI 加密方式、模型、配置目录和依赖版本。新增字段位于加密 JSON 负载中。新增控制器测试使用正式协调器、正式 SQLite 仓储、模拟 HTTP 和测试保护器；录音入口仅在测试项目中替换为桩。

原有按住右 Ctrl、松开停止、一次长按全文润色、长语音参数、Max 词库生成、提示词编辑和 Logo 均保留。

## 升级

1. 在旧版中检查未保存提示，必要时复制或导出当前文字；从托盘选择“退出”。
2. 关闭程序后备份 `%LOCALAPPDATA%\RealtimeTranscription\`，再用 `VoiceInput-Windows-x64-1.2.1.exe` 替换旧 EXE。
3. 在同一个 Windows 用户下运行新版。Key、历史、词库、快捷键与提示词继续从原目录读取。需要排除的历史使用新的会话许可入口确认。

自动测试、发布记录及 EXE 校验信息随源码提供，见 `docs/验证记录.md`、`docs/EXE校验.md` 和 `verification/`。本次为预发布修复构建，尚未执行原生快捷键、WASAPI、DPAPI、目标应用投递以及真实云端模型联调。
