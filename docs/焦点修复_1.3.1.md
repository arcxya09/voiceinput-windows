# 1.3.1 输入位置与焦点修复

## 原代码确认的问题

- 全局按键回调只记录时间，异步消费时才获取目标窗口；回调与消费间的状态变化可能导致目标记录偏移。
- GetGUIThreadInfo 失败或焦点句柄短暂为空都会被等同于明确切换窗口；100 毫秒监视器立即终止该轮。
- 单次 UI Automation 查询在 300 毫秒后判为失败，门锁忙时立即返回，无法容纳辅助功能提供程序的短暂延迟。
- 输入框辅助功能进程必须与顶层窗口进程完全相同，排除了由其他进程提供接口、但原生窗口祖先属于当前窗口的控件。
- 其他键鼠活动只入队，没有同步使投递失效；投递与队列消费存在竞态。

## 改动边界

不强行激活窗口，不调用 SetFocus 或回写保存的选区，不向无法核实的输入框盲发文字。系统短暂缺失焦点采样最多宽限 500 毫秒；宽限期间不注入文字。已知窗口或控件变化立即停止。每批文字前继续检查窗口、键鼠活动和组合输入状态。

UIA 每次查询总等待预算 1200 毫秒，初次捕获及验证最多三次。密码、禁用、只读或已确认的选区变化不会通过重试放行。未完成调用继续占用单一查询门锁；持续卡住时保留文字并停止自动投递。

不记录目标窗口标题、输入框内容、API Key 或音频。错误原因通过现有状态提示和本轮投递原因展示。

## 自动验证与实机范围

新增回归覆盖瞬时缺失、持续缺失、已知目标切换、恢复不重发、同步活动标记、慢辅助功能、超时调用并发控制、取消及异常恢复。所有现有回归同批执行。

需要实机验证：记事本、Word、浏览器普通输入框及富文本编辑器中长按输入；在等待润色时切换窗口、移动光标和确认输入法候选词；反复显示/隐藏浮窗；密码框与只读区域；管理员权限目标窗口。CI 的自动测试不代表上述交互场景均已验证。

## Windows 接口依据

- [GetGUIThreadInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getguithreadinfo)：窗口失去激活期间可能返回无效句柄。
- [UI Automation threading](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-threading)：辅助功能调用应在独立 MTA 工作线程执行，跨线程对象可能因提供程序生命周期失效。
