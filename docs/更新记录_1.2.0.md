# Windows 语音输入法 1.2.0 更新与技术增补

日期：2026-09-12  
状态：已实现的预发布构建；Windows 原生设备与付费账户联调待验证。  
适用：Windows 11 x64，.NET 10 自包含单文件。

本增补替代技术设计 v3.0 及 1.1.0 中关于分片润色、短录音上限和当前会话提词范围的旧规则。键盘钩子、目标校验、凭据保护和原有词库兼容规则继续适用。

## 1. 功能变化

| 用户需求 | 1.2.0 行为 | 操作位置 |
| --- | --- | --- |
| 生成词库可使用 Max 思考 | 专业词库生成可选 Max，普通模式仍可用 | 设置 → AI 生成专业词库 |
| 一次长按全文润色 | 录音期间不发润色请求，松开并收齐尾句后一次调用处理全文 | 默认输入流程 |
| 长语音、减少过度分片 | 默认 10 分钟，最多 30 分钟；断句默认 2.5 秒；合并所有确认结果 | 设置 → 麦克风与操作 |
| 从全部历史提取词条 | 覆盖所有项目的已保存历史，候选带来源，可取消并继续 | 历史记忆 / 设置 |

## 2. Max 思考深度

模型仍为 `deepseek-flash`，开启开关时发送下列参数。这里的 `max` 是服务端正式参数值，并非只改界面名称。[DeepSeek Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)

```json
{
  "model": "deepseek-flash",
  "thinking": { "type": "enabled" },
  "reasoning_effort": "max",
  "max_tokens": 32768,
  "response_format": { "type": "json_object" },
  "stream": false
}
```

请求同时包含系统词库生成规则与 JSON 用户数据。示例省略 `messages`，不作为完整可调用请求。Max 模式不发送无效的温度控制参数；普通模式使用 `thinking.type=disabled`、`temperature=0`，不带 Max 参数。润色和历史提取继续采用非思考模式。

- 每批最多生成 50 个候选，一次目标 1—500 个。要求中的数字不覆盖界面目标数量。
- Max 每批最多等待 180 秒，整次最多 45 分钟；普通模式为 45 秒和 6 分钟。可随时取消。
- 每批输出上限 32,768 Token，包括思考与最终内容。它是本软件的成本边界，不等同于模型的最大输出能力。
- 每批发出前按请求字节数和最大输出量保守预留预算，结束后按 `prompt_tokens + completion_tokens` 结算，思考不另行重复加算。缺失用量则保留预留额。
- 只读取最终 `message.content`；`reasoning_content` 不显示、不保存为词条。响应截断或 JSON 不完整时拒绝当前批，不凑数。
- 余额、预算或超时导致中断时，已完成的生成批次仍可检查与导入。未导入预览在退出后不保留。

## 3. 一次长按对应一次全文润色

### 3.1 输入与收尾

1. 物理按下默认右 Ctrl 后准备本地麦克风，满足 150 ms 阈值且确认可编辑目标后连接百炼。
2. 保持同一 ASR 任务连续上传 PCM。服务端中间结果和 final 只更新识别快照及确认原文，不触发分片润色。
3. 物理松开立即停止麦克风采集；发送末尾音频和 `finish-task`，最多 15 秒等待尾句与 `task-finished`。
4. 按任务与句序拼接本次全部确认原文，包括最后一句和原有自然段。识别有缺口或未确认尾部时保留原文，取消自动输入。
5. 创建一个全文润色请求，以 `current_text` 发送整轮文本；不向 AI 逐片请求，不截取前 600 字，不重试成分片任务。
6. 校验完整响应，采用结果或回退完整确认原文，再校验最初的输入目标并投递。只输出正文，不自动回车发送。

网络传输仍按约 100 ms PCM 帧实时进行，这是音频传输方式，不是文本分片润色。不会把整段长音频先攒在内存后一次上传。

### 3.2 结果与历史一致性

`SessionData` 增加以下加密负载字段，原始 `SegmentData` 保持独立：

| 字段 | 用途 |
| --- | --- |
| `wholePolishState` | `None`、`Waiting`、`Completed`、`Fallback` |
| `wholePolishText` | 完整采用结果，仅 Completed 时用于正文 |
| `wholePolishReason` | 原样、轻量润色或回退原因 |
| `wholePolishOperation` | 拒绝重复处理和迟到响应的版本号 |

自动输入、最近输入、复制、导出、历史查看统一读取整轮结果。原始句子和模型采用结果分别保留。重启时 Waiting 状态降为 Fallback，以原文恢复，不自动重发或重新调用 AI。

“对照与编辑”提供全文对照和原始片段修订两个页签。修订来源片段会使旧全文结果失效，按手改片段重新拼接本地正文，不修改已经写入的外部文档，也不让旧模型响应覆盖新编辑。

### 3.3 润色边界

- 沿用可编辑默认提示词。通读全文后只做局部语言整理，保留句序、逻辑、句式、数字、否定、引用和命中的词库写法。
- 自动处理上限为 30,000 个 Unicode 标量值。超过上限保留完整原文，不截断或分片润色。
- 等待时间为 `clamp(15000 + 字数 × 6, 20000, 120000)` 毫秒；输出预算按 UTF-8 字节数加 512 估计，最少 1,536、最多 98,304 Token，避免长文仍沿用短句输出上限。
- 只采用 `finish_reason=stop` 的完整结果。请求取消、网络错误、输出截断、校验失败或校验超时全部回退完整原文。
- 本地校验仍偏保守，只接受登记过的局部删改；句首“嗯，”“呃，”和明确重复的检查扩展到全文各句。无法确认合理性的改写保留原文。
- 全文不会进入旧的 600 字片段校验上限；长文本校验避免二次方编辑距离计算。

## 4. 长语音与断句

| 配置 | 默认 | 允许范围 / 行为 |
| --- | --- | --- |
| 单次长按 | 600 秒 | 30—1800 秒 |
| 静音断句 | 2500 ms | 200—6000 ms |
| 语义断句 | 关闭 | 使用 VAD 断句 |
| 多阈值模式 | 关闭 | 减少对连续长句的主动切割 |
| 静音心跳 | 开启 | 配合连续实际音频帧发送 |
| 尾部收齐 | 最多 15 秒 | 有缺失则保留确认文字供复制 |
| 输入投递等待 | 随文本长度增加 | 2—60 秒，每批继续校验目标 |

百炼文档允许 200—6000 ms 的静音阈值，并说明多阈值模式用于避免 VAD 片段过长。本版将该模式关闭。服务端仍可能根据自身策略返回多个句子；客户端将这些句子作为同一轮输入处理。[百炼客户端事件](https://help.aliyun.com/zh/model-studio/fun-asr-client-events)

30 分钟是本软件允许配置的应用上限，不是已经实测的服务端时长保证。云端连接、账号限制与实际稳定性仍需在用户账户验证。达到配置时限会停止并取消自动输入，确认文字保留；日常可在时限前松开完成输入。

旧版对“检测到语音结束但仍有 partial”的 5.8 秒判定调大到至少 20 秒，并结合配置的断句时间计算。持续收到服务端心跳时，单纯停顿不会因为旧短时限误中断。网络无响应和来源缺口保护继续保留。

## 5. 从全部历史提取词条

### 5.1 范围

范围是本软件全部项目内已保存的历史语音输入，不读取其他程序、网页或 ChatGPT 的聊天记录。扫描开始时记录历史页边界，分页读取每次最多 100 条；没有历史列表显示 500 条的限制，也没有当前会话提取 5 批的限制。

只使用允许整理会话中的已确认、已保存、未删除来源。没有记录在数据库的输入不能回溯提取。原文优先，用户手动修订过的片段使用修订文本；AI 润色结果不作为学习源，避免模型输出自行变成证据。

### 5.2 分批与进度

每批最多 2,000 个 Unicode 字符、20 个片段；长来源按 Unicode 边界切成提取资料片段，同一批不重复来源 ID。这里的分批只用于历史提词，与语音正文全文润色分开。

界面显示检查会话数、总数、完成批次数、新增数、更新数及未允许整理的跳过数。批次完成后将候选和来源版本游标在同一 SQLite 事务内提交。空结果也记录已处理版本，避免每次重复发送相同普通文本。

取消、预算不足、网络错误、格式错误或程序关闭时，不提交未完成批次。再次点击从所有历史检查未处理的来源版本，已完成批次自动跳过。新录音优先，会取消正在进行的历史任务。

### 5.3 词条与证据

- AI 只提取原样出现的名称、机构、地名、专业术语、型号及有明确用途的固定表达，不建立用户画像或虚构标准写法。
- 每批最多返回 20 词，每词最多 3 条原文证据。证据必须包含词条并能在给定来源片段中逐字找到。
- 新候选保存到**来源项目**，状态为待确认。全历史任务不会把所有项目词库混为全局。
- 同一项目重复词条合并证据，保留已有人工类别、权重、启用状态和写法；大小写与 Unicode 规范化用于去重。
- 删除词条的抑制记录和已禁用项继续有效。每个范围最多 5,000 词；容量不足整批回滚并停止，进度可继续。
- 提交前在事务内重新读取会话和来源，验证学习许可、删除状态、源版本、修订版本及来源切片。已删除或已编辑的旧来源响应不能写回。
- 清除会话继续同步删除相关派生证据，旧异步保存不得复活已删除内容。

## 6. 设置和升级

`settings.json` 的 `schemaVersion` 升至 4，新增 `generationMaxThinking`（默认 false）。示例为部分设置：

```json
{
  "schemaVersion": 4,
  "hotkey": "RightCtrl",
  "holdMs": 150,
  "maxHoldSeconds": 600,
  "silenceMs": 2500,
  "polishEnabled": true,
  "generationCount": 100,
  "generationMaxThinking": false,
  "dailyExtractionTokens": 50000
}
```

旧版默认 120 秒、800 ms 迁移为 600 秒、2500 ms；已有非默认值保持不变。此前手动选用了恰好相同默认值的设置无法与默认区分，升级后可在界面重新调整。现有自定义提示词、Key、项目、记忆与词库继续使用，数据库仍采用版本 1 的兼容加密负载结构。

升级请从托盘退出旧程序，再运行 `VoiceInput-Windows-x64-1.2.0.exe`。在“用量与说明”确认版本，不要删除原用户数据目录。

## 7. 验证与交付

测试覆盖包括整轮一次调用、长于 600 字的全文与末句、段落保留、缺口与超时回退、重复和迟到响应、恢复、Max 参数与思考用量、超过 500 条的跨项目扫描、超过 5 批续跑、取消、删除、手改版本、事务回滚和词条状态保护。具体数量、编译结果、EXE 大小与 SHA-256 以本包[验证记录](验证记录.md)和 [EXE 校验](EXE校验.md)为准。

测试使用模拟 HTTP / WebSocket 与本地测试数据库。尚未在真实 Windows 上验证 WASAPI 麦克风、UIA 控件、长按钩子、DPAPI 或目标应用长文本输入；也未使用真实 Key 调用两家服务。发布包提供实际交叉编译的 Windows x64 自包含 EXE、完整源码及 Markdown 文档。
